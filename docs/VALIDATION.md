# 0.2.31 验证范围与已知问题

公开测试版不承诺全渠道全自动。以下区分既有实测与此次发布检查，不公开个人截图、流水、交易号或原始设备日志。

## 已实现

统一账务与预算、手动记录/编辑/撤销、退款关联、活动预留、用途后补、自定义分类、截图规则、通知解析、实验性无障碍 OCR、可选 DeepSeek、本地备份恢复。

## 已验证

- 此次公开副本独立复跑 155 项测试全部通过；重新编译与 lint 通过（0 错误、6 项警告）。重新构建 APK 与既有待发布 APK 的全部 ZIP 条目内容逐项一致。GitHub 托管 CI 的状态以 Actions 实际结果为准。
- 主机账务与规则测试 155 项通过，包含标准计划、今日额度 55 元消费 20 元后余 35 元、用途后补不重扣、不同交易号隔离、重复读取、退款与内部转账、恢复后的账务一致性。
- 既有 0.2.31 Android 构建和 lint 通过：0 错误、8 项既有警告。
- 一加 PLK110 的特定微信扫码成功页自动记录与扣减、后续详情重复识别不再扣款；短名称 OCR 差异的重复预扣曾复现并已修复、复测。
- 同一台手机上，已截取的微信已有详情任务在回桌面后继续接收结果，重复读取额度不变；未注入人工延迟。
- 支付宝历史版本有真实扫码消费自动预扣和详情去重测试；同商户同金额的新成功页曾被保守标成疑似重复，完整订单号详情可区分。这不等于最新版所有首次成功页都已通过。
- 历史版本在同机固定付款样本做过真实 DeepSeek 对比；小样本不能代表未知页面准确率。此次公开发布不重新调用收费 API。

## 待验证 / 已知限制

- 用户报告从最近任务划掉余白后无障碍断开，原因和修复未完成；不宣称持续后台稳定。
- 新付款即时成功页上“立即离开且随后才完成识别”、真实 DS 慢网络与进程终止恢复仍待验证。
- 更多手机、系统版本、页面布局、微信分身、小程序和 NFC 账单需要逐项验证。
- 无可靠交易号时，疑似重复仍需要核对；不能仅凭同金额同一天自动合并，也不能承诺零漏记。
- OCR / AI 不确定、页面受保护、服务断开或来源权限不足时可能无法自动记录，可手动记账或导入截图。
- 未完成正式签名、商店发布审查、全依赖安全审计及长期稳定性测试。

发布时只分发经筛选的源码、合成测试夹具和 APK；个人测试工具与记录不在公开仓库中。
